# Multi-Lingual Documentation Governance & Anti-Slop Guidelines

Internationalizing repository documentation expands accessibility but frequently introduces severe machine translation slop: broken code blocks, translated CLI flags, mangled file paths, and unidiomatic corporate filler.

This guide defines the non-negotiable rules and synchronization protocol for translating documentation within `well-document`.

## Core Principles

### 1. Verbatim Code & Command Preservation
Never translate executable content:
- Terminal commands (`git clone`, `npx skills add`, `docker compose up`)
- CLI flags (`--target`, `--dry-run`, `--force`, `-v`)
- Package names (`@scope/package`, `well-document`)
- Programming language code blocks (variable names, types, import statements)

### 2. Exact Structural Parity
A translated document must mirror the English canonical version:
- Identical heading hierarchy (H1, H2, H3, H4) in the exact same sequence.
- Identical table column counts and alignment.
- Identical code block count and language identifiers.

### 3. Canonical Backlink Header
Every translated document must begin with an explicit backlink to the primary English documentation:
```markdown
[← Read Original in English](../../README.md)
```

### 4. Grounded Relative Links
Relative links must either:
- Point directly to the root files (`../../LICENSE`, `../../SECURITY.md`) if no localized version exists.
- Point to verified, existing localized sibling documents (`CONTRIBUTING.tr.md`).

## Banned Translation Slop Catalog

Machine translation models routinely replace banned English adjectives with equally vacuous localized puffery. The following translated buzzwords are strictly forbidden:

| Language | Forbidden Marketing Buzzwords | Approved Technical Replacement |
| :--- | :--- | :--- |
| **Turkish (tr)** | *kesintisiz entegrasyon*, *ışık hızında*, *son teknoloji*, *devrim niteliğinde*, *zahmetsizce* | Somut teknik protokoller, spesifik milisaniye gecikme değerleri, POSIX standartları. |
| **German (de)** | *nahtlos integriert*, *blitzschnell*, *spitzentechnologie*, *revolutionär*, *mühelos* | Präzise technische Schnittstellen, standardisierte Protokolle. |
| **French (fr)** | *de manière transparente*, *ultra-rapide*, *technologie de pointe*, *révolutionnaire*, *sans effort* | Spécifications d'API concrètes, latence mesurée. |
| **Spanish (es)** | *perfectamente integrado*, *ultrarrápido*, *vanguardista*, *revolucionario*, *sin esfuerzo* | Parámetros técnicos concretos, interfaces tipadas. |

## Directory & Naming Standards

Choose one consistent pattern for localized documentation across the repository:

### Pattern A: Centralized Translations Directory (Recommended)
```text
docs/
└── translations/
    ├── README.tr.md       # Turkish translation
    ├── README.de.md       # German translation
    ├── README.fr.md       # French translation
    └── README.es.md       # Spanish translation
```

### Pattern B: Co-located Sibling Markdown
```text
.
├── README.md              # Canonical English documentation
├── README.tr.md           # Turkish translation
└── README.de.md           # German translation
```

## CLI Synchronization & Audit Protocol

Use the bundled zero-dependency tool [`scripts/sync-i18n.py`](../../../scripts/sync-i18n.py) to scaffold and verify translations:

### 1. Scaffolding a Translation Template
Extracts the canonical structure and verbatim code blocks into a new translation target:
```bash
python3 scripts/sync-i18n.py --source README.md --init tr --target docs/translations/README.tr.md
```

### 2. Auditing an Existing Translation
Verifies structural parity, code block preservation, and absence of translation slop:
```bash
python3 scripts/sync-i18n.py --source README.md --target docs/translations/README.tr.md --lang tr --audit
```
